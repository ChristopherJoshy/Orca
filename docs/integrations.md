# Provider integration contracts

The product has narrow adapters so optional providers do not become business logic. No credential values belong in source, documentation samples, logs, exports, or agent conversations.

## Stripe

Use Stripe test mode for checkout. The ORCA invoice/ledger remains authoritative. A customer can initiate a hosted session only for their own confirmed invoice; ORCA derives the amount from the current receivable. Session creation carries a persisted ORCA operation key and opaque local checkout ID. Verify webhook signatures against the raw request body; process `checkout.session.completed` only when `payment_status=paid` and process delayed methods on `checkout.session.async_payment_succeeded`. Persist unique provider event IDs and the payment allocation in the same transaction; handle duplicate and out-of-order events idempotently. Reconcile ambiguous session-creation outcomes with the same idempotency key. Never mark an invoice paid on browser redirect alone. If a completed session no longer matches its local attempt or outstanding balance, retain a reconciliation exception instead of silently posting it.

## Email

Customer-account verification and password-reset messages use the Resend adapter directly. Workspace admin signup does not require email: it creates the account and session immediately, leaves `user.verified` false, and shows the no-budget email notice before entering the workspace. Customer portal linking, password reset, and document-send requests still require both Resend credentials and a sender; when either is absent, they return 503 before creating or changing records. With the provider configured, approved invoice and quotation send requests are written to the PostgreSQL outbox in the same transaction as their audit event. The cancellable outbox worker renders document data from stored invoice snapshots or quotation lines, escapes untrusted text with Go's `html/template`, and sends through Resend with a stable tenant-bound idempotency key. Attempts, delivery timestamps, and bounded error details are retained on the outbox event; provider failure does not roll back the business document. The worker runs immediately and repeats at `ORCA_EMAIL_INTERVAL` (default `1m`).

Resend documents a 24-hour idempotency-key retention window. Retry ambiguous provider outcomes within that window to preserve the provider-side duplicate protection; ORCA's persistent event key remains stable. See [Resend idempotency keys](https://resend.com/changelog/idempotency-keys). Fake-provider tests cover successful delivery, retry after an ambiguous failure, duplicate processing, tenant-bound keys, and HTML escaping. No live customer email has been sent; production delivery still requires a verified sender and provider credentials.

## Groq and agent model calls

The Go API uses Groq's OpenAI-compatible chat-completions API with a configurable model. The default is `openai/gpt-oss-20b`: Groq currently lists it as a production model at about 1,000 tokens/second, with a 131,072-token context and local tool use. This suits ORCA's latency-sensitive, serial tool loop. `openai/gpt-oss-120b` remains configurable for reasoning-heavy tasks; Groq lists it at about 500 tokens/second and describes it as its flagship high-capability open-weight model. These are provider-published generation speeds, not measured end-to-end ORCA latency. See [Groq's supported model catalog](https://console.groq.com/docs/models), [tool-use support](https://console.groq.com/docs/tool-use/overview), and [latency guidance](https://console.groq.com/docs/production-readiness/optimizing-latency).

The bounded loop supports scoped record search, report summary, invoice explanation, invoice simulation, and proposals for a limited set of reviewed billing actions. The backend executes an approved supported action only after rechecking actor, tenant, input hash, and resource version. Set request timeouts, tool limits, and structured schemas. Model availability is not a dependency for ordinary product operations. Tool responses are authoritative for numbers and mutations; the model may summarize but not invent a result. Run records persist, but in-flight work does not resume after API restart.

One earlier direct Groq chat-completions request returned HTTP 200 in the local environment. On 2026-10-31, authenticated model-list and tool-call probes from this environment and the VPS instead received Cloudflare HTTP 403 error 1010, while the unauthenticated model-list endpoint returned its expected HTTP 401. This prevents confirming the configured credential or testing the selected model end to end; the failure is not evidence that the key itself is invalid. Keep this distinct from offline tool/approval tests.

## Configuration and status

Environment names are documented in `.env.example`. `ORCA_BILLING_INTERVAL` and `ORCA_EMAIL_INTERVAL` control the two in-process workers. Configure `STRIPE_SECRET_KEY` with a test-mode secret key and `STRIPE_WEBHOOK_SECRET` with the endpoint signing secret. Readiness should report whether required configuration exists and whether a measured provider health check succeeded; never display secret values. Manual payment, invoices, reports, and other non-provider workflows stay usable without provider configuration. When Resend is unavailable, workspace signup remains usable without verification and explains that automatic email was not funded; customer portal linking, password reset, invoice email, and quotation email show a branded explanation and make no request. Those email-dependent APIs return 503 without creating unusable records or changing document state. Provider-specific installation/account provisioning is owner-managed. Live provider behavior is pending until sandbox evidence appears in history.
